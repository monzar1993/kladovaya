# Кладовая — учёт продуктов дома

**Сайт:** <https://monzar1993.github.io/kladovaya/>

Одностраничное приложение без сервера и без сборки. Живёт на GitHub Pages,
а данные хранит **в этом же репозитории**: список — в `data/db.json`, фото — в `data/img/`.
Каждое изменение становится коммитом, так что история репозитория — заодно журнал «что и когда забрали».

- **Общая кладовая на двоих** — Igor и Anna видят один и тот же список с любых устройств. На входе выбираете
  себя и вводите общий пароль. В карточке видно, кто добавил и кто последним менял позицию,
  а в истории репозитория каждый коммит подписан: `[Anna] Забрано 1 шт.: Молоко`.
- **Список** — фото, название, срок годности и сколько осталось штук; кнопки **−/+** в каждой строке.
  Если до конца срока 3 дня или меньше (или он уже прошёл), срок горит красным. Закончившиеся позиции
  остаются в списке приглушёнными — их можно пополнить кнопкой «+». Поиск и фильтры «Скоро истекают» / «Просрочено».
- **Карточка** — фото, название, описание, срок, поле количества с кнопками −1 / +1, QR-код позиции и печать этикетки.
- **Нижняя панель** — «Добавить» и «Забрать по QR» (сканер камерой или распознавание с фото).

QR-код — это ссылка на карточку (`…/#/item/<id>`). Обычная камера телефона откроет карточку,
а «Забрать по QR» сразу предложит забрать 1 шт.

## Публикация (≈5 минут)

1. **Создайте репозиторий** на GitHub (например, `pantry`) и загрузите в него содержимое этой папки:
   ```bash
   git init && git add . && git commit -m "Кладовая"
   git branch -M main
   git remote add origin https://github.com/<логин>/pantry.git
   git push -u origin main
   ```
   Или просто перетащите файлы на странице репозитория: *Add file → Upload files*.

2. **Включите GitHub Pages**: *Settings → Pages → Build and deployment → Source: Deploy from a branch*,
   ветка `main`, папка `/ (root)`. Через минуту сайт будет доступен по адресу
   `https://<логин>.github.io/pantry/`.

3. **Откройте сайт** и войдите (выберите себя, пароль по умолчанию — `149`).

4. **Настройки → Создать общую кладовую.** Ссылка «токен GitHub» там открывает форму создания
   fine-grained токена с уже заполненными названием, сроком (366 дней) и правом *Contents: Read and write*.
   Останется выбрать *Repository access → Only select repositories →* ваш репозиторий и нажать
   *Generate token*. Вставьте токен в форму, задайте общий пароль и нажмите «Создать». Если до этого вы
   уже что-то добавили в браузере, приложение предложит перенести эти позиции в общую кладовую.

5. **Пригласите остальных.** В настройках появится QR-код и ссылка-приглашение. Наведите на код камеру
   телефона (или отправьте ссылку), выберите себя и введите общий пароль. Это нужно один раз на каждом
   устройстве, включая ваши собственные.

Когда токен истечёт, приложение скажет об этом — создайте новый и вставьте его в **Настройки → Заменить токен**.
Ссылки-приглашения при этом продолжат работать.

## Как это устроено

- Токен GitHub хранится в репозитории в файле `data/auth.json` **в зашифрованном виде** (AES-GCM,
  ключ выводится через PBKDF2 из общего пароля и **ключа кладовой**). Ключ кладовой — 256 случайных бит;
  он передаётся только в ссылке-приглашении (после `#`, поэтому не уходит даже на сервер GitHub Pages)
  и хранится в браузерах подключённых устройств. Пароль нигде не хранится.
- Пользователи перечислены в `config.js` (`users`), пароль у всех общий.
- После входа приложение читает и пишет `data/db.json` напрямую через GitHub API — сервер не нужен.
- Если два устройства правят список одновременно, приложение перечитывает файл и применяет свою
  правку заново, так что изменения не затирают друг друга.
- Нажатия −/+ копятся меньше секунды и уходят одним коммитом («Добавлено 3 шт.: Молоко»). В файл пишется
  разница, а не итог, поэтому если два устройства одновременно что-то взяли, учтутся оба изменения.
- Фото сжимаются в браузере до ~1000 px (обычно 60–150 КБ).
- Владелец и имя репозитория на `*.github.io` определяются по адресу страницы. Для своего домена
  укажите их в `config.js`. Там же — `warnDays`: за сколько дней до конца срока подсвечивать красным.

## Безопасность — важно

- **Короткий пароль вроде `149` сам по себе не защищает**: три цифры перебираются за секунды. Поэтому
  токен зашифрован ещё и ключом из ссылки-приглашения, которого в репозитории нет: без ссылки один
  пароль ничего не даёт. **Ссылка-приглашение и есть доступ к кладовой** — отправляйте её только своим.
  Кто знает ссылку и пароль, может менять ваш репозиторий (только его: токен ограничен одним репозиторием).
- Если ссылка попала не туда: **Настройки → Заменить токен** с галочкой «Выдать новую ссылку-приглашение»
  (старые перестанут работать), а старый токен отзовите на GitHub.
- В **публичном** репозитории список продуктов и фото видны всем. Если это нежелательно, сделайте
  репозиторий приватным (GitHub Pages для приватных репозиториев доступен на тарифе GitHub Pro).
- Без подключения GitHub данные хранятся только в текущем браузере (localStorage).

## Запуск локально

Модули ES не работают с `file://`, поэтому нужен любой статический сервер:

```bash
python3 -m http.server 8080
```

и откройте <http://localhost:8080>. Камера в браузере работает только на `https://` или `localhost`.

## Файлы

```
index.html            точка входа
config.js             настройки (обычно не нужно трогать)
css/style.css         стили, светлая и тёмная тема
js/app.js             экраны и маршрутизация (#/, #/item/<id>, #/add, #/scan, #/settings, #/join/<ключ>)
js/store.js           хранилища: localStorage и GitHub Contents API
js/auth.js            вход, сессия, ссылка-приглашение, подключение GitHub, смена пароля
js/crypto.js          шифрование токена и ключ кладовой (WebCrypto)
js/qr.js              генерация QR и сканер (BarcodeDetector или jsQR)
js/image.js           сжатие фото
data/                 создаётся приложением: db.json, auth.json, img/
```

Библиотеки QR (`qrcode-generator`, `jsQR`) подгружаются с CDN только когда нужны.
